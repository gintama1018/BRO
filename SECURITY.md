## 1. Core Security Philosophy

> **The Non-Negotiable Axiom:**  
> **Artificial Intelligence is NEVER the security authority.**

```
UNSAFE (Probabilistic):
Untrusted URL / Page ───► LLM Inference ───► "Looks safe to me" ───► Allowed to Render

DETERMINISTIC & SAFE (NovaBrowser):
Untrusted URL / Page ───► Deterministic Security Gate ───► ALLOW / WARN / BLOCK
                                 │
                                 └──► LLM (Only explains reasons or summarizes AFTER allow)
```

1. **Deterministic & Auditable:** Allow, warn, and block decisions are strictly generated by deterministic code, verified threat feeds, and mathematically sound heuristics. Decisions are explainable down to the exact rule or heuristic trigger.
2. **"Unknown" is NOT "Safe":** The absence of a URL in a blocklist does not confer trust. If a site is unclassified, it remains in the `UNKNOWN` state and receives baseline sandboxing and heuristic checks. It is **never** labeled or treated as `KNOWN SAFE`.
3. **Defense-in-Depth:** Navigation security operates in multiple successive filters (URL canonicalization → threat feed matching → typosquat/heuristic analysis → redirect chain tracing → subresource network filtering → cosmetic DOM element hiding).
4. **Zero Trust for Untrusted Web Content:** Web scripts running inside WebView/Chromium are treated as hostile. Untrusted web code has zero access to native capabilities, internal browser controls, or AI execution pipelines.
5. **Empirical Honesty:** We reject marketing absolutes such as "100% secure" or "zero malicious links". Offline threat feeds capture known malware hosts, while heuristics flag statistical anomalies; novel or zero-day threats can exist.

## 2. Threat Model & Attack Surfaces

### 2.1 Attack Surface Breakdown

| Attack Vector | Threat Description | NovaBrowser Countermeasure |
|---|---|---|
| **Known Malware / Drive-by Exploits** | Distribution domains, phishing kits, botnet C2 hosts. | Embedded offline URLhaus malware database (5,057+ domains) + fast binary/hash lookup. |
| **Typosquatting & Homoglyphs** | Lookalike domains (e.g. `paypa1.com`, Cyrillic `xn--...`). | Punycode canonicalization, Levenshtein distance against protected brand registry, and Shannon entropy analysis. |
| **Malicious Redirect Chains** | Multi-hop redirects masking final malicious destinations (`A -> B -> C -> payload`). | Stateful redirect tracking enforcing a 4-hop limit and intercepting SSL-downgrade (HTTPS → HTTP) attacks. |
| **Dangerous Executable Downloads** | Stealth or deceptive downloads of `.apk`, `.dex`, `.sh`, `.exe`, `.bat`. | Streamed into app-private `.nova_quarantine/` sandbox; SHA-256 digest calculated; requires explicit user release. |
| **Adware, Trackers & Fingerprinters** | Cross-site tracking scripts, telemetry pixels, invasive ad popups. | Offline $O(\text{labels})$ hash tree matching over EasyList/EasyPrivacy rules (9,578 domain rules) + 118 cosmetic CSS selectors. |
| **Cross-Site Cookie Tracking** | Third-party surveillance cookies across web sessions. | Third-party cookies blocked by default (`setAcceptThirdPartyCookies(false)`), `DNT: 1`, and `Sec-GPC: 1` header injection. |
| **Site Permission Creep** | Unmonitored camera, microphone, or geolocation capture. | SQLite-backed `site_permissions` registry with granular toggles and one-tap revocation. |
| **Privileged Bridge Abuse** | Malicious JavaScript invoking native Android methods via `@JavascriptInterface`. | **Hard Boundary:** Zero privileged native APIs exposed to WebView DOM content. |
| **Indirect Prompt Injection** | Deceptive page text crafted to hijack future local LLM tool calling. | Data/instruction boundary enforcement, strict JSON schema validation, and human-in-the-loop authorization. |
| **Threat Feed Staleness** | Outdated local rule snapshots. | Timestamp and snapshot metadata displayed in settings; opportunistic background updates via Android WorkManager. |

## 3. The Android JS Bridge Hard Boundary

One of the most dangerous vulnerabilities in mobile browsers is exposing native Java/Kotlin methods to the DOM via `@JavascriptInterface`.

```
+-------------------------------------------------------------------+
|                        UNTRUSTED WEB CONTENT                      |
|                  (Arbitrary Webpages, Ads, Scripts)               |
+-------------------------------------------------------------------+
                                  │
                                  X   <─── HARD BARRIER: NO BRIDGE
                                  │
+-------------------------------------------------------------------+
|                     PRIVILEGED ANDROID APIS                       |
|          (File System, Camera, SMS, Contacts, Shell, NDK)         |
+-------------------------------------------------------------------+

+-------------------------------------------------------------------+
|                   TRUSTED BROWSER UI & CONTROLLER                 |
|       (Native Address Bar, Tabs, Settings, Shields, QuadView)     |
+-------------------------------------------------------------------+
                                  │
                                  ▼   <─── Validated, Permissioned Calls
+-------------------------------------------------------------------+
|                        BROWSER CONTROLLER                         |
+-------------------------------------------------------------------+
```

### Architectural Rules for Bridge Isolation:
1. **Zero Privileged Bridges:** Never attach `@JavascriptInterface` objects that expose file system access, reflection, runtime execution, or private browser state to untrusted WebView content.
2. **Read-Only Content Extraction:** Content extraction for Reader Mode and text analysis utilizes sandboxed `evaluateJavascript` queries that return sanitized strings to native code. The DOM cannot call back into the host application.
3. **No Direct DOM-to-Tool Route:** A webpage script can **never** trigger Browser Controller tools (e.g. `open_url`, `switch_tab`, `clear_history`). Tools can only be invoked by the trusted native UI layer.

## 4. Deterministic Security Gate Pipeline

Every navigation request (user-typed, link-clicked, redirect, or AI-originated) traverses the Security Gate before the Web Engine initiates a network connection:

```
Incoming Navigation Request
          │
          ▼
[ Stage 1: URL Canonicalization & Normalization ]
          │
          ▼
[ Stage 2: Local Threat Feed Matching (URLhaus / EasyList) ]
          │
          ├───► [ MATCH FOUND ] ───► High Confidence BLOCK (RiskState.BLOCKED)
          │
          ▼ (No direct blocklist hit)
[ Stage 3: Heuristics & Brand Impersonation Analysis ]
          │
          ├───► [ HIGH ANOMALY ] ──► SUSPICIOUS / HIGH RISK Warning
          │
          ▼
[ Stage 4: Multi-hop Redirect Chain Verification ]
          │
          ├───► [ DEEP CHAIN / DOWNGRADE ] ──► WARN / BLOCK
          │
          ▼
[ Stage 5: Dual-Layer WebView Interception ]
          ├─── Layer 1: WebViewClient.shouldOverrideUrlLoading (Top-level navigations)
          └─── Layer 2: WebViewClient.shouldInterceptRequest (Subresource filtering)
          │
          ▼
[ Stage 6: Render Page (Engine Sandbox) ]
```

### Stage 1: URL Canonicalization & Normalization (`UrlCanonicalizer`)
- Converts all hostnames to lowercase.
- Recursively decodes nested percent-encodings (e.g. `%252e` → `%2e` → `.`).
- Converts internationalized domain names (IDN / Punycode) into canonical Unicode to expose Cyrillic/homoglyph substitutions (e.g. `xn--pypa-4ve.com` → `paypa1` or Cyrillic `а`).
- Strips misleading user-info segments (e.g. `https://google.com@evil-site.com`).
- Normalizes default ports (e.g. `:80` for HTTP, `:443` for HTTPS) and trailing slashes.

### Stage 2: Threat & Reputation Snapshot (`ThreatFeedManager`)
- Evaluates against local SQLite table `security_rules` and embedded binary datasets (`urlhaus_domains.txt`).
- Operates **100% offline** in $\le 3\text{ ms}$. No external cloud queries are made during navigation checks.

### Stage 3: Heuristics & Typosquat Detection (`HeuristicsEngine`)
- **Levenshtein Distance:** Compares the canonical domain against a built-in registry of high-profile financial, technology, and service brands (Google, GitHub, PayPal, Microsoft, Amazon, etc.).
- **Shannon Entropy:** Detects dynamically generated / algorithmic domains (DGA) (e.g. `x89dfa78bf23kj.biz` exhibits abnormally high entropy).
- **Subdomain Deception:** Flags branded subdomains masquerading on unrelated base domains (e.g. `paypal.com.account-verify-secure.ru`).

### Stage 4: Redirect Chain Protection (`RedirectTracker`)
- Tracks navigation lineage (`Origin -> Hop 1 -> Hop 2 -> Destination`).
- Intercepts redirect chains exceeding 4 hops to mitigate redirect cloaking.
- Detects protocol downgrades (`HTTPS -> HTTP`) to defend against SSL-stripping attacks.

### Stage 5: Dual-Layer WebView Interception
- **Top-Level Navigation:** Intercepted by `WebViewClient.shouldOverrideUrlLoading()`, routing candidate URLs through `DeterministicSecurityGate.evaluate()`.
- **Subresource Interception:** Intercepted by `WebViewClient.shouldInterceptRequest()`. Evaluates subresources (scripts, beacons, iframes) against `AdBlockEngine` using in-memory hash lookups in $O(\text{labels})$ time. Blocked requests receive an empty `WebResourceResponse`.

## 5. Download Protection & Physical Quarantine Sandbox

Drive-by downloads and misleading executable extensions represent critical mobile attack vectors. NovaBrowser enforces strict filesystem isolation:

```
   [ Incoming Download Request ]
                 │
                 ▼
       [ Verify MIME & Extension ]
                 │
   ┌─────────────┴─────────────┐
   │                           │
Safe MIME                Risky Executable / Script (.apk, .dex, .sh, .exe, .js)
   │                           │
   ▼                           ▼
[ Status: SAFE ]         [ Status: QUARANTINED ]
   │                           │
   ▼                           ▼
Save to Downloads/       Stream into App-Private Sandbox: .nova_quarantine/{UUID}.quarantine
                         Compute SHA-256 Digest on the Fly
                               │
                         Prompt User: Explainable Risk Interstitial + SHA-256 Fingerprint
                               │
                       ┌───────┴───────┐
                       │               │
                  [ Delete ]     [ Explicit Override ]
                       │               │
                       ▼               ▼
                   [ BLOCKED ]   Sanitize & Move to Public Downloads [ COMPLETED ]
```

1. **Classification:**
   - **Safe:** Plain text, standard images, audio/video media.
   - **Risky:** Android Application Packages (`.apk`), Dalvik executables (`.dex`), scripts (`.sh`, `.js`, `.vbs`, `.bat`), system binaries (`.exe`, `.so`), compressed archives containing executables.
2. **Physical Sandbox Quarantine:** Risky files are never written directly to public storage. They are streamed into an app-private sandbox directory (`.nova_quarantine/`) with a unique UUID filename.
3. **Cryptographic Integrity:** A running SHA-256 checksum is computed on the byte stream during ingestion.
4. **User-Controlled Release:** The user is presented with an explainable interstitial displaying filename, size, detected threat classification, and SHA-256 fingerprint. Only upon explicit confirmation is the file released to public storage.

## 6. Ad, Tracker & Privacy Boundaries

### 6.1 Subresource Filter Implementation
- `AdBlockEngine` maintains an in-memory prefix/suffix domain tree representing EasyList and EasyPrivacy rules (9,578 domains).
- Lookup executes in $O(\text{labels})$ time (typically 2–4 hash lookups per subresource).
- Subresources matching trackers or ad networks are silently dropped with zero latency impact on main page layout.

### 6.2 Cosmetic Filtering Engine
- `CosmeticEngine` matches host domains against 118 curated selector rules (`cosmetic_selectors.txt`).
- Upon `onPageFinished`, matching CSS hiding rules (`display: none !important;`) are injected into the DOM to collapse blank ad slots and sticky banners.

### 6.3 Site Shields & Granular Controls
- Users can customize shield behavior per domain via `SiteShieldManager` (`site_shields_settings` table):
  - Toggle all shields on/off
  - Toggle ad and tracker blocking
  - Toggle cosmetic element hiding
  - Toggle JavaScript execution
  - Toggle third-party cookie blocking

### 6.4 Explicit Technical Boundary
**Known Limitation (In-Stream Video Ads):** Server-side ad insertion (SSAI) where video advertising is delivered from the exact same CDN infrastructure and hostname as the video content (e.g. YouTube CDN media chunks) cannot be filtered using domain blocklists without breaking legitimate media streaming. NovaBrowser does not claim "ad-free YouTube streaming" because domain-level blocking cannot distinguish CDN video segments.

## 7. Explainable Security UI Specification

Users must never see an ambiguous "Page Blocked" notice. Every security intervention is transparent and actionable.

### Risk States

| Risk State | Meaning | Address Bar / UI Presentation |
|---|---|---|
| **`KNOWN SAFE`** | Verified top-tier domain with clean history and valid TLS. | Subtle lock badge in omnibox. |
| **`UNKNOWN`** | Uncategorized domain. No malicious record, but no positive reputation. | Neutral address bar; **never labeled "Safe"**. |
| **`SUSPICIOUS`** | Triggers heuristic alarms (homoglyphs, typosquatting, DGA entropy). | Amber warning banner with review prompt. |
| **`HIGH RISK`** | High-probability brand impersonation or multi-hop redirect loop. | Full-screen red warning interstitial. |
| **`BLOCKED`** | Explicit match in URLhaus malware database. | Hard red block screen. Navigation paused. |

### In-App Security Diagnostics Self-Check Runner
Accessible via `SettingsActivity` (`btnRunDiagnostics`):
1. **Benign Baseline:** `https://example.com` → Evaluates to `ALLOW`, `RiskState.UNKNOWN`.
2. **Homoglyph Spoof:** `https://paypa1.com` → Evaluates to `WARN`, `RiskState.SUSPICIOUS` (Target: PayPal).
3. **Malware Interception:** `http://malware-test.urlhaus.ch` → Evaluates to `BLOCK`, `RiskState.BLOCKED`.
4. **SSL Downgrade:** Protocol downgrade redirection → Evaluates to `WARN`.
5. **AdBlock Enforcement:** `doubleclick.net` → Evaluated and blocked by `AdBlockEngine`.
